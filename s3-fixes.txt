S3 Screen / Display Fixes
=========================
Tracked during hurricane watch + moon phase development (March 2025).


1. Moon phase JPEGDEC byte-order fix
-------------------------------------
Problem: Moon JPEG decoded with RGB565_BIG_ENDIAN (matching all other
JPEGDEC usage in the codebase), but the decoded pixels were passed
directly to draw16bitRGBBitmap which expects native little-endian
RGB565. Result: pixels appeared invisible (scrambled near-black values).

Fix: After JPEGDEC decode into s_moonBuf, bulk-convert all pixels
from big-endian to native LE via __builtin_bswap16() before any
display call. The weather frame pipeline already did this conversion
inside scaleSpriteTo410x360() but the moon path was missing it.

Location: decodeMoonPhase() — bswap loop after successful decode.


2. Moon complication placement — bottom AMOLED border
-----------------------------------------------------
Problem: Initial implementation stamped moon pixels into the 410×360
frame buffer (inside the weather animation area). User wanted the
moon in the 71px black border below the frame (AMOLED Y=431-502).

Fix: Replaced stampMoonIntoFrameBuf() with drawMoonComplication()
that calls draw16bitRGBBitmap directly at the border position.
Horizontally centered, vertically centered in the 71px border strip.
Uses s_moonDrawn one-shot flag (AMOLED retains pixels); resets on
fillScreen clears via s_amoledClearBeforeNextPresent.

Location: drawMoonComplication() called from presentScaledBuf()
after chunk blit loop, same pattern as drawHurricaneRebootHint().


3. Hurricane mode progress bar — full-screen red background
-----------------------------------------------------------
Problem: Hurricane mode download progress bar only colored the bar
area itself red, not the full screen background.

Fix: Added fillRect calls in drawProgressBarUi() to paint areas
above and below the progress bar + text with bg color (0xA800
dark red in hurricane mode). showMessage() also uses red bg.

Location: drawProgressBarUi(), showMessage().


4. Hurricane "Reboot for local weather" hint — draw ordering
------------------------------------------------------------
Problem: The reboot hint text was drawn from applyBarsToBuf() which
runs BEFORE fillScreen(0x0000) in presentScaledBuf(), so the hint
was immediately wiped on screen clears.

Fix: Moved drawHurricaneRebootHint() call to after the chunk blit
loop in presentScaledBuf(). Added s_hurricaneHintDrawn flag that
resets on screen clear, matching the one-shot AMOLED retention
pattern.

Location: presentScaledBuf() — after chunk loop.


5. Radar "Clear" time-since-check display
------------------------------------------
Problem: When radar shows "Clear" (no precipitation), there was no
indication of how stale the check was.

Fix: Added RTC_DATA_ATTR s_lastRadarCheckUtc timestamp, set when
radar returns clear. Display shows "Radar: Clear 12m" with minutes
since last check. Both top-bar render locations updated.

Location: s_lastRadarCheckUtc global; radar clear path; bar render.
